# 1. Welcome And Framing

## Purpose

Open the session by making GitHub Copilot feel practical, approachable, and relevant to cloud automation work. The goal is to help attendees understand that this is not a session about replacing technical judgment. It is about using Copilot to get started faster, explore options, and iterate with more confidence inside Visual Studio Code.

## Key Message

GitHub Copilot is most useful when you treat it as a coding partner: you bring the intent, context, constraints, and judgment; Copilot helps create drafts, explain unfamiliar material, and move work forward.

## Talking Points

- Welcome attendees to the Azure Systems Management User Group session.
- Explain that the session is beginner-friendly and demo-oriented.
- Frame the audience broadly: cloud engineers, systems administrators, DevOps practitioners, automation engineers, and developers.
- Define "vibe coding" as a practical workflow, not magic: describe the goal, generate a starting point, review the result, test it, refine it, and keep moving.
- Set the expectation that generated code needs review, especially for cloud and production environments.

## Suggested Opening

"Tonight we are going to look at GitHub Copilot in Visual Studio Code through the lens of cloud automation. The goal is not to pretend the AI knows your environment better than you do. The goal is to use it as a fast, useful partner for getting from an idea to something you can inspect, test, and improve."

## Possible Visuals

- Session title slide.
- Simple workflow diagram: idea -> prompt -> draft -> review -> test -> refine.
- Screenshot of VS Code with Copilot Chat visible.

## Demo Setup Notes

- Keep the first demo low-risk and easy to understand.
- Avoid starting with production Azure access or anything that mutates resources.
- Consider using a local script or mock data first, then move toward Azure-specific examples.

## Timing

Target: 5 minutes.
